# Word lists

Par ships three lists, generated by [`tools/wordlists/build.py`](../tools/wordlists/build.py)
and committed under [`src/data/`](../src/data). The output is committed so that building,
testing and running the app never require Python — only regenerating them does.

| list | size | what it is |
| --- | --- | --- |
| guess dictionary | 12,972 | every word a player may type |
| answer list (v1) | 3,000 | the original possible answers (puzzles 0–259) |
| answers v2 (v2) | 9,570 | candidate answer pool for weighted selection (puzzle 260+) |
| starter pool (v1) | 5,000 | legacy pool for the daily house starter (puzzles 0–259) |
| starters v2 (v2) | 5,000 | house starter pool derived from answers v2 (puzzle 260+) |

The answer list is deliberately far narrower than the dictionary. Losing to a word nobody has
heard of is not a challenge, and in a game where friends compare scores an obscure answer
wrecks everyone's day equally while telling you nothing. The dictionary stays generous
because probing with an odd-but-real word is a legitimate tactic.

## Source

Collins Scrabble Words 2019, fetched from the
[`scrabblewords`](https://github.com/scrabblewords/scrabblewords) repository and pinned by
SHA-256 in the generator. The download is cached in `tools/wordlists/.cache/` and gitignored.

Two reasons for a Scrabble lexicon rather than a plain word list. It is the size and register
the spec asks for, and **the Scrabble intersection is also the proper-noun filter** — these
lexicons exclude names, which is what keeps WAYNE and DUBAI out of a frequency-ranked answer
list.

CSW19 yields exactly 12,972 five-letter words, comfortably inside the spec's `~10k–13k+`
range. An earlier plan unioned CSW19, CSW21, NWL2023 and NSWL2023 to reach 13,019; CSW21 turns
out to be a subset of CSW19 at five letters and the North American lists add 47 words, so the
union bought almost nothing for four sources and four licensing positions. See
[decision 0001](decisions/0001-plan-reconciled-with-spec.md).

**Licensing.** Collins Scrabble Words is a copyrighted compilation of HarperCollins, and the
source file opens with their notice. What is committed here is a derived five-letter subset
used as a game dictionary, which is the same use every Scrabble-adjacent hobby project makes
of these lists.

State the position plainly rather than comfortably. This repository is public, so the derived
subset is redistributed and no argument from privacy is available. The claim is narrower than
permission: a noncommercial game shipping a word list as its dictionary is not competing with
the compilation as a product, and that is a settled norm in this corner of hobby software. It
is not a licence, and HarperCollins has not granted one.

If that stops being a trade worth making, switch the source to a permissively licensed lexicon
and regenerate — the generator takes the source as a single constant. Expect it to move the
answer list, the starter pool and the version identifier, and to leave `PAR` stale, which moves
the golden score snapshots with it.

## Frequency ranking

Word frequencies come from [`wordfreq`](https://pypi.org/project/wordfreq/), pinned in
[`requirements.txt`](../tools/wordlists/requirements.txt). It reports Zipf values on a log
scale where 1.0 is roughly one occurrence per hundred million words and 5.0 is a very common
word.

The pin matters. A different corpus reorders the answer list and the starter pool, which
changes the word-list version identifier and invalidates existing share links.

Ranking is by frequency descending with **alphabetical tie-breaking**, never by set or dict
iteration order. The order of the guess dictionary is part of the scorer's contract: entropy
ties break by guess index and the ranking decides which guesses the search explores, so a
reordered dictionary is a different dictionary.

## Asserted properties

The generator refuses to emit output unless all of these hold, and
[`tests/data/wordlists.test.ts`](../tests/data/wordlists.test.ts) re-checks them against the
committed files, because the generator does not run in CI.

- All three lists are lowercase, five letters, no duplicates.
- The answer list and the starter pool are subsets of the guess dictionary.
- The starter pool is approximately 90% five-distinct-letter words and 10% words with exactly
  one doubled letter, within a percentage point.
- No starter has two pairs, or any letter appearing three or more times. Those are excluded
  from the pool entirely rather than counted in either bucket.
- The committed version identifier is what the committed lists actually hash to.

## Tail quality, honestly

The generator prints where each list bottoms out, because "words people actually know" and "no
XYLYL-tier junk" are requirements worth measuring rather than assuming.

```
answer list       3000   cutoff 'infra' at Zipf 2.90
starter pool      5000   4500 distinct (90.0%), 500 one-pair
  distinct tail   'atopy' at Zipf 1.57
  one-pair tail   'furry' at Zipf 3.56
  below Zipf 2.0  892 (17.8%) of the pool
```

**The answer list is comfortable.** Its cutoff sits at Zipf 2.90 among words like `heave`,
`knoll`, `mulch` and `suave`. Nobody loses a day to a word they have never met.

**About 1.2% of answers double as first names.** The Scrabble intersection does the job it was
picked for — capitalised-only names like WAYNE and DUBAI are absent — but it cannot exclude
words that are simultaneously a name and a lowercase dictionary entry, and frequency ranking
mildly favours them because the name usage inflates the count. Thirty-six of the three
thousand are in this class, roughly one puzzle every three months.

Most are unambiguously real words that happen to also be names: `frank`, `grant`, `mason`,
`pearl`, `hazel`, `penny`, `terry`, `sandy`, `patty`. A handful read as names first — `sammy`,
`danny`, `peggy`, `monty`. We ship them. Filtering would mean sourcing and vendoring a names
list to remove one awkward day a quarter, and most of what it removed would be collateral.

**The starter pool's distinct-letter tail is the weak spot, and it is arithmetic rather than
a tuning mistake.** Only 5,701 five-distinct-letter Collins words appear in the frequency
corpus at all. A 5,000-word pool at 90% distinct needs 4,500 of them, so it necessarily reaches
79% of the way down that list, and the bottom holds words like `dumka`, `gryce`, `hongi` and
`ngoma`. About one day in six draws a starter below Zipf 2.0.

The available trade, if that ever grates:

| distinct-letter floor | largest 90/10 pool |
| --- | --- |
| Zipf 1.0 (corpus presence) | 6,334 |
| Zipf 1.5 | 5,175 |
| Zipf 2.0 | 4,008 |
| Zipf 2.5 | 2,978 |

Pushing the tail to Zipf 2.0 means a pool of about 4,000, below the spec's stated
`~5,000–6,000`. We ship 5,000 — the low end of the range, which is the point in it that best
serves the quality bar — with a hard floor at corpus presence. Nothing in this corpus falls
strictly between Zipf 0 and 1.0, so that floor is exactly equivalent to excluding words the
corpus has never seen. `xylyl` itself measures 0.0 and is excluded.

This costs less than it looks. A house starter is played for you, so you never have to know
the word, and starter quality moves the outcome by roughly a tenth of a guess. It is a
raised-eyebrow problem, not a fairness one. Changing it is one constant in the generator.

## Word selection v2 (Game 260+)

Starting at puzzle 260 (`CUTOVER_PUZZLE_NUMBER = 260`), Par switches to **Word selection v2**,
which expands the candidate answer space from 3,000 words to 9,570 words while introducing
non-uniform, frequency-weighted selection.

### Candidate list generation (`answers_v2`)

The candidate pool is generated by [`tools/wordlists/build_v2.py`](../tools/wordlists/build_v2.py)
and committed to [`src/data/answers_v2.generated.ts`](../src/data/answers_v2.generated.ts).

1. **CSW19 Base**: Starts with all 12,972 five-letter words in Collins Scrabble Words 2019.
2. **Plural Removal**: Strips simple 4-letter + 's' regular plurals where the 4-letter stem is a
   valid noun in CSW or WordNet (e.g. `cats`, `dogs`, `birds`).
3. **Intrinsic 's' Retention**: Words legitimately ending in 's' that are not plurals are carefully
   preserved (e.g. `chaos`, `basis`, `focus`, `virus`, `glass`, `bonus`, `cross`, `dress`, `alms`, `lens`).
4. **Pure 3rd-Person Verbs**: Verbs ending in 's' without noun senses (such as `seems`, `wants`,
   `knows`, `gives`, `feels`, `takes`) identified by POS taggers (`lemminflect` VBZ without noun usage)
   are isolated and appended at the bottom of the list in their own dedicated block.
5. **Structure and Demarcation**:
   - **Main block**: 9,349 words (indices `0` to `9348`), sorted descending by `wordfreq` Zipf score
     with alphabetical tie-breaking.
   - **Pure verbs block**: 221 words (indices `9349` to `9569`), sorted descending by `wordfreq` Zipf
     score with alphabetical tie-breaking within the block.
   - **Total**: 9,570 words.
   - The file exports explicit boundary constants:
     - `ANSWERS_V2_MAIN_COUNT = 9349`
     - `ANSWERS_V2_VERBS_START_INDEX = 9349`
     - `ANSWERS_V2_VERBS_COUNT = 221`
     - `ANSWERS_V2_TOTAL_COUNT = 9570`

To regenerate `answers_v2`:

```bash
PYTHONPATH=tools/wordlists/.pydeps python3 tools/wordlists/build_v2.py
```

### Deterministic weighted selection

Rather than picking uniformly across all 9,570 candidates, words are drawn in four tiers by frequency rank:

| Tier | Index Range | Word Count | Weight | Total Tickets | Ticket Range | Probability |
| --- | --- | --- | --- | --- | --- | --- |
| Tier 1 | 0 – 2,499 | 2,500 | 10 | 25,000 | 0 – 24,999 | ~59.42% |
| Tier 2 | 2,500 – 4,999 | 2,500 | 4 | 10,000 | 25,000 – 34,999 | ~23.77% |
| Tier 3 | 5,000 – 7,499 | 2,500 | 2 | 5,000 | 35,000 – 39,999 | ~11.88% |
| Tier 4 | 7,500 – 9,569 | 2,070 | 1 | 2,070 | 40,000 – 42,069 | ~4.92% |
| **Total** | | **9,570** | | **42,070** | | **100.0%** |

Tier 4 contains the tail of the main vocabulary plus all 221 pure 3rd-person singular verbs.

The draw function `drawWeightedIndex(puzzleNumber, salt)` in
[`src/engine/daily/puzzle.ts`](../src/engine/daily/puzzle.ts) maps a deterministic ticket
$t \in [0, 42070)$ generated via SplitMix32 into a word index in $O(1)$ time.

### House starters v2 (`starters_v2`)

In v1, the starter pool was 5,000 words drawn from the broader dictionary, which included regular plurals
(`MASKS`, `BOATS`, etc.) and words not present in the v2 answer list. Once plural filtering was applied to
`answers_v2`, drawing a word like `MASKS` in Game 300 made it immediately obvious to the player that the house starter
had a 0% chance of being a hole-in-one.

To guarantee that every house starter in the v2 era is a legitimate candidate answer with positive probability,
`starters_v2` is derived dynamically from `answers_v2`:

1. **Top 5,000 of `answers_v2`**: Starters are drawn from the most frequent words in `answers_v2`.
2. **No Triple Letters (Option B)**: In accordance with Philosophy §9 (*"Never a triple; that's past interesting and into unfair"*),
   any word containing $\ge 3$ of the same letter (such as `eerie`, `geese`, `mummy`, `error`) is skipped.
3. **Zero Bundle Overhead**: Rather than shipping a separate generated TS file, `startersV2` is filtered from `answersV2`
   at module initialization in ~3.5ms. It scans to index 5,061 in `answersV2` to collect exactly 5,000 valid starters.
4. **Properties**:
   - 100% of starters are valid answers in `answers_v2`.
   - 0% simple regular 4-letter + `'s'` plurals.
   - 0% triple-letter words.
   - 3,207 distinct-letter words (64.1%), 1,665 single-pair words (33.3%), 128 two-pair words (2.6%).

### Cutover and compatibility

- **Puzzles 0 to 259**: `drawPuzzle` uses the uniform draw from the original 3,000 `answers` list and the legacy 5,000 `starters` pool.
- **Puzzle 260 onwards**: `drawPuzzle` uses the weighted draw from `answersV2` and draws house starters from `startersV2`.
- **Dual Lexicon & Path A Weighted Scoring**: The scoring worker maintains both `legacyLexicon` (3,000 answers) and
  `v2Lexicon` (9,570 answers with weights `answersV2Weights`). Puzzles $\ge 260$ score against `v2Lexicon` with
  probability-weighted search (`SCORER_VERSION_V2 = 2` and `PAR_V2`), ensuring candidate expectations match
  selection likelihood. Past games ($< 260$) and historical share links continue to evaluate against `legacyLexicon`
  with unweighted search (`SCORER_VERSION_V1 = 1` and `PAR_V1 = 3.7100`) with zero drift and without triggering version warnings.

## Regenerating

Only needed when the lists themselves should change. Requires Python 3.10 or newer.

```bash
python3 -m pip install --target tools/wordlists/.pydeps -r tools/wordlists/requirements.txt
PYTHONPATH=tools/wordlists/.pydeps python3 tools/wordlists/build.py
```

`--refresh` re-downloads the lexicon instead of using the cache. A virtualenv works too but
fails under some sandboxes, which is why the documented path installs to a directory.

Afterwards:

1. Check the printed sizes and tail frequencies look sane.
2. `npm test` — the property tests must still pass, including the version-hash check.
3. **Recompute `PAR`.** It is defined as the mean guess count for strong play from house
   starters, so new lists mean a stale constant and a mis-centred score.
4. Commit the regenerated `src/data/` alongside whatever prompted the change.

The version identifier changes automatically, so share links created against the old lists
will show a mismatch notice instead of silently rescoring against different words.
